## Teacher's brief (Finnish, summarized)

- Implement a fully dynamic, GENERIC Object Pool. Purpose: keep in-game objects in
  memory and REUSE them instead of constantly Instantiate/Destroy. Also give ONE
  central, uniform interface to create & remove enemies, bullets, collectables, etc.
- Build it on `Dictionary` + `Queue`, with THREE classes:
  1. `PoolEntry` — `[Serializable]` helper: `SpaceObject prefab` + `int initialSize = 10`.
  2. `SOPoolSpaceObjects` — ScriptableObject holding `List<PoolEntry> poolObjects`
     (the pool config; one instance per game; adding a type = add a row, no code change).
  3. `ObjectPool` — the pool itself:
     `Dictionary<SpaceObject, Queue<SpaceObject>> pools` (prefab → queue),
     `Dictionary<SpaceObject, SpaceObject> objectPrefabs` (instance → prefab),
     + methods `Register<T>`, `Get<T>`, `Return<T>` (all `where T : SpaceObject`).
- Mechanics: Register enqueues `initialSize` pre-instantiated (inactive) instances;
  Get dequeues from the front (or instantiates one if empty), activates + calls `Init()`;
  Return calls `ResetObject()`, deactivates, enqueues to the back.
- Usage: ApplicationController loads the SOPoolSpaceObjects from a Resources folder,
  builds the ObjectPool, and registers every entry. Then:
  - firing a bullet = `ObjectPool.Get<Bullet>(weapon.BulletPrefab as Bullet)`;
  - returning a bullet = in Bullet, when it is no longer in camera view,
    `ObjectPool.Return(this)` (uses `CameraHelper.SpriteBoundsInCameraView`);
  - spawning enemies = `ObjectPool.Get(...)` + position via `CameraHelper.GetSpawnPositionAbove(...)`.
- The brief itself flags a limitation: referencing a prefab by LIST INDEX
  (`PoolObjects[i]`) is not intuitive and a unique ID would be better. (Deferred —
  see §Scope NOT-DONE.)
