## 🚨 Known template issues (rule violations in the STARTER code)

Found during audit of `Assets/Scripts/PlayerController.cs`:

**Issue 1 — PlayerController handles INPUT directly (InputSystem_Actions, `moveInput`, `OnFire`)**
- Rule broken: §2.7 (separation) + §2.1 (input belongs to InputController)
- Detail: template predates InputController, which arrives later per teacher.
- Action: leave for now — input logic leaves this class when InputController arrives.

**Issue 2 — PlayerController plays AUDIO (`AudioController.Instance.PlaySoundEffect("Laser_Shoot_1")`)**
- Rule broken: §2.7 (separation)
- Detail: audio playback decisions belong to AudioController; the player should only
  report "I fired" and let the controller play the sound.
- Action: leave for now, flag in later refactor task.

**Issue 3 — PlayerController is instantiated via Instantiate<PlayerController>(
Resources.Load<PlayerController>("PlayersShip")) in ApplicationController.Init()**
- Rule broken: none (it's used as a prefab component, which is fine per §2.2)
- Detail: note that once PlayerController : SpaceObject, this instantiation still works.
- Action: none — just be aware of it.

**Issue 4 — `moveSpeed` is a [SerializeField] on the player**
- Rule broken: borderline §2.8 (minimize Inspector usage)
- Detail: genuinely needed for tuning the player ship; acceptable to keep for now.
- Action: keep, revisit if a later task moves tuning data out of scripts.

**Assumption (pending Q4):** Issues 1 and 2 stay until a later task explicitly refactors
input/audio out of PlayerController. Do NOT silently "fix" them in this task.
