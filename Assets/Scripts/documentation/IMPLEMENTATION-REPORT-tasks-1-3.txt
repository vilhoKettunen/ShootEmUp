## 2. Key decisions (teacher's answers → code)

| # | Decision (from your answers) | Where it lives |
|---|---|---|
| 1 | Reuse template easing; use it for movement patterns | MovementPatterns.Eased calls Kryz.Tweening.EasingFunctions.OutCubic |

| 10 | Bullet despawns on ANY SpaceObject hit + lifespan | Bullet.OnCollision + Bullet.Update |
| 11 | LEVEL IS GLOBAL across weapons; weapons switch/level via powerups later | PlayerController.currentLevel (kept across SetWeapon) |
| 12 | Test: [1-5] switch, E up, Q down, immortal dummy w/ HP in UI | PlayerController.HandleTestHooks, TestDummy, UiViewHud |

### Design rules applied (AGENTS.md §2.1–§2.8)
- **2.1** PlayerController/ApplicationController modified in place — never renamed.
- **2.2** Each runtime object carries EXACTLY ONE custom script (Bullet /
  EnemyVulture / EnemyFalcon / TestDummy / PlayerController). No helper components.
- **2.3** No tags anywhere — all distinctions are C# types + IDamageable interface.
- **2.4** MovementPatterns + Weapon are plain C# (no MonoBehaviour); SOs are data.
- **2.5** No scene lookups — everything boots from the Main scene via
  ApplicationController.
- **2.6** spawnOrigin cached at Init; no per-frame Find/GetComponent.
- **2.7** Math in MovementPatterns, data in SOs, execution in each object's Update.
- **2.8** ALL per-variant tuning (enemy moves, weapon tables, bullet motion) lives
  in ScriptableObject assets, not code branches.

## 3. The 5 weapons (defaults set per Q-T3-1 / Q-T3-6)

bullet speed AND bullet movement pattern (the easing/pattern set in use).

### 4.2 Create the 5 bullet prefabs (in Assets/Prefabs/Bullets/)
For EACH weapon (repeat the same recipe 5×):
1. Create empty GameObject → name PlayerBullet_MG (… _Laser, _Spread,
   _Plasma, _Orbital).
2. Add Sprite Renderer → sprite: any small ship/rocket from
   Assets/models/kenney_spaceShooterExtension/PNG/Sprites X2/ (Rockets work well).
3. Add Box Collider 2D → size ~ (0.3, 0.6) → **Is Trigger: ON**.
4. Add Rigidbody 2D → Type: Dynamic → **Gravity Scale: 0** (motion is
   transform-driven; this guarantees trigger callbacks).
5. Add the **Bullet** script. (NO movement SO field on the script — it is
   INJECTED at spawn; do NOT look for one.)
6. Save as prefab (drag to scene or Ctrl+S in prefab stage).

### 4.3 Create the 2 enemy prefabs (+ later 5 more) — in Assets/Prefabs/Enemies/
- **EnemyVulture**: empty GO → Sprite (e.g. Ships/spaceShips_002.png) →
  Circle Collider 2D (Is Trigger ON) → Rigidbody 2D (Dynamic, Gravity 0) →
  **EnemyVulture** script → save.
- **EnemyFalcon**: same recipe, sprite spaceShips_004.png, script **EnemyFalcon**.
- (Roster slots for later: EnemyWasp, EnemyHornet, EnemyRaptor, EnemyCondor,
  EnemyStinger — same recipe, different sprite; the 4 Rockets sprites are

### 4.5 Create the 5 weapon ScriptableObject assets

### 4.6 Create the HUD view + register it in the UI prefab
1. Create empty GameObject → name UIView_HUD → add Canvas + Canvas Scaler
   (reference resolution 1920×1080) + Graphic Raycaster.
2. Under it create 3 Text (Legacy) children:
   - Text_Weapon   (top-left)       initial: "Weapon: MachineGun"
   - Text_Level    (top-left, below) initial: "Level: 1"
   - Text_Health   (top-right)      initial: "Dummy HP: 100"
3. Add **UiViewHud** script to UIView_HUD → set **DefaultState = Visible** →
   assign the 3 texts to weaponText / levelText / healthText.
4. Save UIView_HUD as a prefab (any folder, e.g. Assets/Prefabs/UI/).
5. Open Assets/Prefabs/Resources/UI.prefab → find the **UiViewsList** component
   (same object as UIController) → add ONE item to Views:
   - UiLayer: LayerHUD
   - View: UIView_HUD prefab
6. Save UI.prefab. (The HUD now auto-appears in every scene that has the UI.)

### 4.7 Assign the PLAYER weapon (PlayersShip prefab)
Open Assets/Prefabs/Resources/PlayersShip.prefab:
- PlayerController → **Default Weapon**: MachineGun
- PlayerController → **Weapon Specs** (size 5), in this exact order (test keys):
  1. MachineGun   2. LaserCannon   3. SpreadGun   4. PlasmaBlaster   5. OrbitalCannon
- (Recommended) Add Box Collider 2D (Is Trigger ON) + Rigidbody 2D (Dynamic,
  Gravity 0) to the player GO so enemy/obstacle contact damage works.
- Save.

### 4.8 Wire the ApplicationController (test-spawn assets)
The ApplicationController is auto-created at runtime (singleton). To assign
Inspector values, in the Main scene:
1. Create empty GO → name ApplicationController → add the script.
2. Enable **Enable Test Spawns** (default true).
3. Assign:
   - vultureMovement = VultureMovement SO,   vulturePrefab = EnemyVulture
   - falconMovement = FalconMovement SO,     falconPrefab = EnemyFalcon
   - testBulletMovement = TestBulletMovement SO, testBulletPrefab = PlayerBullet_MG
   - testDummyPrefab = TestDummy
   - (optional) debugText = any Text in scene
4. Save the Main scene. (Alternatively uncheck enableTestSpawns for clean play.)

### 4.9 Sanity checks (30 seconds)
- Project window: no yellow/missing-script icons anywhere.
- Project Settings → Tags and Layers: no custom tags used (rule 2.3).
- Each prefab (open each one): EXACTLY ONE custom script (rule 2.2).

## 5. HOW TO TEST (Play Mode, from the Main scene)

### T1 — Movement (Task 2)
1. Press Play. Console should show the `[Test] Spawned ...` lines.
2. **Vulture** (left, x=-2): moves DOWN while WIGGLING side-to-side (sine).
3. **Falcon** (right, x=2): moves DOWN on a smooth EASED curve (OutCubic).
4. **Test bullet** (bottom center): flies STRAIGHT UP, disappears after ~2 s
   (duration) even without hitting anything.
5. Watch ≥ 10 s: no per-frame warnings in the Console.
PASS = all four move as described + clean console.

### T2 — Firing + weapon feel (Task 3)
1. Hold fire (Space / Jump action): MachineGun bullets stream up, fast (0.15 s).
2. Press **2** (LaserCannon): slower stream, slower bullets.
3. Press **3** (SpreadGun): bullets wiggle (sine path) while rising.
4. Press **4** (PlasmaBlaster): wider, slower wiggle.
5. Press **5** (OrbitalCannon): single eased bullet every 0.8 s.
6. HUD (top-left) shows the weapon name + level changing with each press.
PASS = 5 visually distinct fire patterns + HUD updates.

### T3 — Damage + level (Q-T3-1/Q-T3-4)
1. Level 1 MachineGun: shoot the **TestDummy** (center). Console:
   `[TestDummy] Took 15 damage → HP: 85` (100 → 85).
2. Press **E** ×4 → Level 5. HUD shows "Level: 5".
3. Shoot dummy again: `Took 10 damage` (L5 MachineGun dmg = 10).
4. Press **Q** → Level 4 (dmg 12). Switch to **2** (LaserCannon) — level is
   KEPT (global): shoot → `Took 21 damage` (L4 LaserCannon).
5. Keep shooting the dummy to 0: `HP: 0` — **it does NOT die** (immortal).
PASS = numbers match §3 tables, level persists across switches, dummy survives.

### T4 — Enemy death + collision
1. With a high level, focus fire on the **Vulture** (HP 10, dies in 1 shot).
   It disappears (Despawn) — console clean, no "missing reference" errors.
2. Same for the **Falcon**.
3. Fly the player INTO an enemy: console prints
   `[Player] Took 1 damage.` — player stays alive (lives = later task).
PASS = enemies die at 0 HP, player reports hits, no null-reference spam.

### T5 — Rules checklist (once, after the above)
- [ ] Console has ZERO errors over a 30 s Play session.
- [ ] No tags used (Project Settings → Tags and Layers).
- [ ] One custom script per prefab (open each prefab).
- [ ] enableTestSpawns OFF + Play = only the player exists, zero errors

## 7. Troubleshooting
| Symptom | Cause / fix |
|---|---|
| "No defaultWeapon assigned" warning | §4.7 not done — assign MachineGun on PlayersShip |
| Player doesn't fire | Default Weapon empty — see §4.7 |
| Enemy doesn't move | SO asset not assigned on ApplicationController (§4.8) |
| Bullet flies but never despawns | Duration = 0 on its SO → set to 1.5–3 s |
| Bullets/enemies fall down | Rigidbody 2D Gravity Scale ≠ 0 (see §4.2–4.4) |
| No collision at all | Collider missing "Is Trigger: ON" or Rigidbody 2D missing |
| HUD not visible | UiViewsList item missing in UI.prefab (§4.6 step 5) |
| Dummy HP text not updating | HUD text fields unassigned (§4.6 step 3); console still shows HP |
| Pressing 1–5 does nothing | weaponSpecs list shorter than the key index (§4.7 order) |
